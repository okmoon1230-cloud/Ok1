# Ambition: 더 깊고 검증 가능하게 일하기

출처: Felix Rieseberg, "How to be more ambitious: A tutorial for humans with models" (`references/felix-rieseberg-article.md`).
핵심: 모델이 *더 큰* 일이 아니라 *더 깊고 더 높고 더 넓은* 일을 하도록, 그리고 결과를 **외부 수단으로 검증**하도록 요청을 재설계한다.

## 절차

1. **요청 진단**: 사용자의 요청을 아래 세 축에서 점검한다.
2. **재설계 제안**: 각 축에서 빠진 부분을 짚고, 개선된 작업 계획(또는 프롬프트)을 2~5줄로 제시한다. 사용자가 이미 명확히 지시했으면 확인 질문 없이 바로 수행한다.
3. **수행**: 재설계된 방식으로 실제 작업을 한다. 도구(코드 실행, 파일 읽기, 검색)를 실제로 쓴다.
4. **검증**: 모델 자신의 판단이 아니라 실행 가능한 외부 수단으로 확인하고, 무엇으로 검증했는지 보고한다.

## 세 축

### 고도 (Altitude): 목표 너머의 목표
- 개별 작업이 아니라 최종 결과를 묻는다. "무엇이 다음에 일어나야 하는가?"
- 예: "이 수치 정리해줘" → "이 결과로 어떤 결정을 내려야 하는지, 근거와 반대 논거까지 제시해줘."
- 창의적 작업에는 효과가 낮다. 회의로 논의할 성격의 일에 특히 유효하다.

### 깊이 (Depth): 최고 전문가의 도구와 원자료
- **같은 도구 사용**: 어휘만 바꾸지 말고 방법을 바꾼다. 마크다운 표 대신 실제 계산, 통계 모델, 데이터베이스.
- **어려운 목표를 가능하다고 제시**: 10초→5초가 아니라 200ms를 목표로 하고, 불가능해 보여도 계속 시도한다.
- **알던 것에 도전**: 원자료를 주고 가정을 적대적으로 검증한다.
- **새 지식 생성**: 데이터 깊숙이 들어간 뒤 사각지대를 찾는다.
- **외부 심판**: 스스로 채점하지 않는다. 코드 실행, 테스트, 통계 출력, 원문 대조로 확인한다.

### 범위 (Range): 여러 분야의 관점
- 명사를 동사로 바꾼다. "발표자료" → "바쁜 사람들이 30분 안에 인과 이야기를 믿고 결정하게 만드는 일".
- 역할극 금지. "투자자처럼 써줘"가 아니라 그 분야 사람이 실제로 하는 *조사 방법*을 수행한다.

## 심화 프롬프트 (요청을 재설계할 때 사용)

> 더 큰 버전이 아니라 더 깊은 버전을 원한다. 다시 쓰기 전에 (1) 이 분야 최고 전문가가 내가 요청하지 않은 무엇을 할지, (2) 가공된 자료 대신 어떤 원자료에서 시작할지, (3) 어떤 구체적 방법과 도구를 쓸지, (4) 나나 너 말고 무엇이 결과가 맞다는 걸 보여줄지를 말하라. 그다음 정확히 그것을 요구하도록 프롬프트를 다시 써라.

## 이 사용자 맥락 (물리치료학과 교수: 강의, 논문, 보고서)

- 통계: 요약표 대신 코드로 실행 가능한 분석, 효과크기와 95% CI, 가정 검정까지. 데이터가 없으면 지어내지 않고 `[DATA REQUIRED]`로 표시.
- 문헌: 인용·수치·DOI는 PubMed 등으로 실제 확인. 확인하지 못한 것은 확인 못 했다고 명시. 절대 날조하지 않는다.
- 강의자료/보고서: 학습자나 독자가 결과로 무엇을 하게 되는지(고도)에서 거꾸로 설계.
- 기존 논문 작성 스킬(paper-planner, statistics, results-writer 등)과 함께 쓸 때, 이 스킬은 깊이 기준과 검증 기준만 보태고 해당 스킬의 절차를 대체하지 않는다.

## 주의

- 과잉 적용 금지: 사소한 요청까지 확대하지 않는다.
- 능력 한계: 접근하지 못하는 데이터나 도구가 필요하면 가정하지 말고 무엇이 필요한지 말한다.
- 검증하지 못한 결과는 "검증됨"이라고 쓰지 않는다.
